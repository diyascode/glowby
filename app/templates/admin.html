The scam-engine exam — dev, validation, hidden

      
Testing, not training. Every case has an answer key (verdict bands, required red flags). Dev ships with the code and lists every failure. Validation and hidden are uploaded here and live only in the database; the hidden split reports rates only — its texts are never shown, so nobody can tune to it. Launch goals: ≥97% of dangerous cases high/critical · <5% of legitimate flagged · 0 actions that point at the sender's own number or link · ≥99% valid output. Robustness re-runs the scams with typos, leet, slang and injected instructions.

A message already in any split is skipped. Have someone who is not tuning the rules write the hidden set.

        
        

      

    


    

      
Scam engine calibration — run the corpus, learn from the misses

      
Runs the labelled corpus through the same rules readers get (no model, no lookups: free and instant). The shipped seed corpus has 70 scam shapes and 70 legitimate messages (25 of them hard negatives — real alerts that look like scams); add your own below — one per line, scam: <text> / ok: <text>, or paste the UCI SMS Spam Collection as-is (spam<TAB>text / ham<TAB>text). "Learn" sends the misses and false alarms to the review model, which proposes new pattern shapes — proposals only, you decide (≈10¢).

      
      

      

      

    


    

      
Glowby's scam dataset — redacted, consented, human-reviewed
